Gate 1 — what we're building

Agent Chat (working name) · requirements review · 2026-07-27
The idea in one breath

A private Slack-style chat app on your Mac/PC and iPhone, kept in sync, where every coworker is an agent you created — its own name, personality and skills. Some work for you in the background and message you first. Any agent is one hotkey away. You and a few friends each connect your own Claude subscription, so everyone's usage bills to their own plan.

What version 1 includes

  • Connect your Claude subscription — sign in once; your agents run on your plan.
  • Create agents — name, avatar, written personality, and per-agent ability switches.
  • Abilities — web search, open links, read/write files in a folder you choose, scheduled tasks (“daily 9am summary”), and background jobs (“work on this, ping me when done”).
  • Proactive agents — they can message you first; on iPhone that arrives as a push notification.
  • Chat everywhere — 1-on-1 chats, channels holding several agents addressed by @mention, and a desktop global hotkey popup to message any agent from anywhere.
  • iPhone app via TestFlight — full chat + notifications, synced with desktop.

What version 1 leaves out (on purpose)

  • Android (later), public App Store launch, voice/video, sharing agents with others.
  • Agents sleep when your desktop app is closed. The engine is built so we can move it to an always-on server later — but v1 doesn't rent that server.

Honest risks

Biggest one: letting an app sign users in with their Claude subscription (rather than a pay-per-use API key) is a newer mechanism, and we must verify it's allowed and working for third-party apps before building on it. That check is the first task of the architecture stage. Fallback if blocked: each user pastes an API key instead — everything else stays the same, but usage becomes pay-per-use.
  • iPhones don't allow apps to keep working in the background — so the phone is a window to your agents, not their home. Desktop off = agents pause (until the future server upgrade).
  • Agents talking freely to each other could loop and eat through a subscription's usage limits — the decision below caps that.

2. In a channel with several agents, when may an agent speak?
Recommended

When @mentioned, capped

An agent replies when you tag it or it's clearly addressed; agent-to-agent back-and-forth stops after 3 turns.

If wrong: caps are a dial — easy to loosen later.

Free conversation

Agents may chime in and debate each other freely. Livelier, but loops can silently burn your usage limits.

If chosen: expect to hit subscription limits much faster.
