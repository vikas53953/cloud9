Agentic engineering pipeline

Our loop is the spine. Agents do the work. Builder never reviews their own work. Conductor oversees the room. Three Dex upgrades sit inside plan and build — not as a second system.

The room (how real software teams work)

One room. Clear roles. Pure agentic loop — you are not the reviewer of every step.

Main agent · Conductor
Orchestrator. Spawns one agent per job. Relays between author and reviewer. Never merges own work. Never writes the feature and reviews it. Keeps the board honest. Escalates to you after 2 reject rounds.
Author agents
Write the plan, or write the code. Own one issue, one branch. Fix only blockers from review.
Reviewer agents
Different agents. Briefed to find what is wrong. Verdict: Blockers · Out of scope · Agree. Never edit the work they review.
You — name the ask · settle escalations · approve direction when the conductor brings a clean page. You do not sit in every author↔reviewer round.
Never self-review Builder ≠ reviewer. Always. Pure agentic loop.
One issue · one agent · one branch Conductor assigns; nobody doubles up.
One artifact per stage Reviewer judges only that plan file or PR.
Hard stop after 2 rejects Conductor escalates to you (or a fresh third agent).

Stolen from Dex — inside our loop (not a second pipeline)

  • Light program design — for big work only: files, signatures, test names, least-confident calls. Lives in the plan artifact. Small fixes skip it.
  • Vertical slices — build thin end-to-end pieces, not “all backend then all UI.” Re-steer after each slice while cheap.
  • Compact to docs — at every stage and every slice end, write decisions to disk. Fresh session resumes from docs, not chat memory.
