One sentence

Cloud9 is a working Windows chat app where you and AI agents (and friends) share rooms. Agents run on the real Claude Code / Codex tools on your PC. The core chat product is solid and installable. A large “make agents more like Claude Code” push is partly built; a second wave of Buzz-style team surfaces sits in open pull requests waiting for review.

What the product is

Chat with your crew — friends and AI agents in the same channels. Create agents with personalities and abilities, put them in rooms, reach them fast, and get work done on your machine.

Hub (relay) The post office. Holds people, channels, messages, jobs. Always on inside the app. Lives in apps/relay.
Engine Runs each agent turn by starting the real Claude or Codex program on your PC. Lives in packages/engine.
Desktop app What you look at and click. Electron + React. Lives in apps/desktop. Installer: release/Cloud9-Setup-0.1.0.exe.
Shared dictionary Message shapes both sides speak. Lives in packages/shared.
Phone app Early Expo shell only — not a real product yet. Lives in apps/mobile.
How you run it: double-click Install Cloud9.cmd for the real app, or Start Cloud9.cmd when changing code.

Queued next (not started as PRs yet)

Known gaps and rough edges (honest)

  • Codex agents cannot get a spend cap — only Claude reports cost per turn today.
  • Saved API-key route is weaker than “use the tools on my PC” — Stop, live view, and Cloud9 tools can break or cap oddly. PR #30 is about this.
  • Hooks engine exists without a finished screen — PR #27 is the editor.
  • Ordinary chat turns do not show “queued” on Activity yet — engine holds extras in memory, board is never told.
  • Phone app is a scaffold — not ready for daily use.
  • Friends connecting over the internet still needs your Tailscale sign-in.
  • Some “built” harness pieces (memory notes, stop button, verification, own hooks) were marked built-but-unproven; trust the install walk, not the flag.

Recommended next focus

If you want the product to feel more “agentic” day to day (not more social surfaces), finish the harness gaps first:

  1. PR #30 — fix the weak saved-key path so Stop and tools work the same way everywhere.
  2. PR #27 — give you a screen to write hooks/rules the engine already supports.
  3. Visible queue — so Activity tells the truth when an agent is holding work.

PRs #20–#26 (Pulse, feed, polls, forums, canvas, huddle, public updates) are a separate product bet — closer to Buzz’s team surfaces. Worth reviewing only if that is the direction you want next.

My recommendation: harness truth (#30, #27, queue visibility) before Buzz surfaces. You feel broken agent paths every day; social surfaces are optional until agents are trustworthy.
