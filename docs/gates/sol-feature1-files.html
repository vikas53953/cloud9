Five product truths

The rules that must stay true

The screen is called Files.

It is one bounded worktable across the rooms the viewer can access, not a technical storage browser. Each row still obeys its own room boundary and any narrower restriction.

Screen truth: people look for “Files”, so that is what Cloud9 calls it.

Every file shows its maker when known.

When a proven source turn is present, the record also shows which chat, task, schedule or worktree turn produced the file. Cloud9 does not invent a turn when that proof is absent.

Trail truth: maker when known; source turn only when proven and present.

Old versions are never rewritten.

Cloud9 keeps up to 20 versions. A retained old row and its bytes are never edited or reused; when the limit is reached, the oldest version is pruned under the stated retention rule.

Version truth: “immutable” means unchanged while retained, not kept forever.

The room remains the permission wall.

Files are room-visible by default. A room manager may narrow one file to selected current human members; room managers remain included, and access can never expand beyond the room.

Permission truth: leaving the room removes the route to the file.

Links are declared, typed and same-room.

An agent declares a link through the private turn record. Cloud9 does not infer links from markdown or let someone hand-edit provenance on screen. Only the safe public shape is shown.

Link truth: the screen follows proven links; it does not guess.

The alias ruling

Reviewer concern · parked
Exact ruling in plain words

A nested disk path is shared as only the safe filename.

If an agent points to subdir/report.md on disk, Cloud9 shares only report.md. Any offered name that still contains / or \ is refused before anything is stored. The nested path therefore cannot create a second alias in the shipped flow, so no code change was needed for this reviewer concern.

Choices still owned by Vikas

Deliberate, reversible calls

I chose Files — Vikas may overrule.

This is the screen name because it matches the existing “Files agents made” wording and says what a person will find.

I chose same-room typed links only — Vikas may overrule.

Cross-room links are held back because even showing a file name could leak information across separate permission walls.

I chose agent-declared links — Vikas may overrule.

The turn carries a typed private record. The Files screen reads that record; it does not guess links from prose or allow a manual provenance rewrite.

I chose owned one-read snapshots — Vikas may overrule.

The engine owns the captured bytes before publish. It does not return to a changing file path later and accidentally bless different content.
