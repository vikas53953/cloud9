Recommended implementation order

Only the six rows marked GAP are buildable proposals; row 21 is a separate PARTIAL/NOT STARTED verification proposal. Each buildable gap is unassigned in TRACKER.md; this audit owns no implementation.

  1. Saved-key provider parity (tracker 16): stop/live/tools/session truth before any other SDK-route work. Dependency: none.
  2. Queue visibility and fair concurrency (17): expose the existing two-slot queue and cancellation without adding clocks. Dependency: run lifecycle state only; queue visibility is independent of saved-key provider parity (16).
  3. Real project and plugin skill instructions (19): explicit allow-list and on-demand loading. Dependency: an owner-setup/security decision outside this audit.
  4. Conversation compaction and remaining-room visibility (18): preserve thread-first context while saying what was dropped. Dependency: session/run evidence.
  5. Hooks editor (15): write/list/remove existing hook rules and show firing/refusal history. Dependency: none; keep events/actions bounded.
  6. Handoff context beyond a channel (20): deliver memory/run/artifact/thread pointers. Dependency: artifact/memory access plus queue/run contract.
  7. Verification runner and visible check status (21): owner-approved project recipe and durable evidence. Dependency: repository/worktree action model and run records; verification is independent of saved-key provider parity (16) and queue visibility (17).

Scope decisions: Workflow is active manual-v1 only; Pulse/social, huddles/calls, account/privacy parity, public publishing, paid/subscription actions, and the money default remain outside this audit. Do not turn them into tickets from this page.
